# Data card

**Every dataset in this repository is synthetic and was authored for this project.** There is no
real factory data, no real personal data, no scraped data, and no third-party dataset anywhere in
the tree. Nothing here may be presented, exported or referenced as if it came from an actual
apparel manufacturer.

Four datasets exist. Each is described below with its provenance, size, licence status, known
biases and the limits on what may be concluded from it.

| # | Dataset | Location | Size | Generated by |
|---|---|---|---|---|
| 1 | Operational seed dataset | Written into PostgreSQL by `make seed` | ~101 orders, 50 tables | `app/seed/generator.py` (seeded RNG) |
| 2 | Synthetic SOP corpus | `data/synthetic/sops/` | 30 documents + 1 superseded version | Hand-authored |
| 3 | Adversarial fixtures | `data/synthetic/adversarial/` | 2 documents | Hand-authored |
| 4 | Labelled NLP/IR evaluation sets | `data/eval/` | 260 notes, 56 questions | Script + hand review |

## 1. Operational seed dataset

**Purpose.** Development, testing, the demonstration scenario, and every evaluation run.

**Provenance.** Generated entirely by
[`services/backend/app/seed/generator.py`](../../services/backend/app/seed/generator.py) from the
fixed vocabulary in `app/seed/vocabulary.py` — the same vocabulary the SOP corpus and the labelled
datasets are authored against, so order refs, material codes, line codes, operation names and
defect codes match exactly across the whole demo.

**Determinism.** Every random choice comes from one `random.Random(rng_seed)` (default
`20260917`); nothing reads the wall clock; every date is relative to a caller-supplied
`anchor_date`. Two runs against two empty databases produce byte-identical business facts, proven
by `tests/integration/test_seed.py::test_seed_is_deterministic_across_fresh_databases`. Low-level
`allocations` row counts can vary by a few rows because line primary keys are genuine UUIDv4 and
the planner breaks same-date/same-shift ties on `str(line_id)`; no order's own stored facts change
([`docs/evaluation/synthetic-data.md`](../evaluation/synthetic-data.md)).

**Size** (representative; `make seed` prints the authoritative `SeedSummary.counts`):

| Group | Count |
|---|---|
| Organizations / factories | 1 / 2 (`KTN`, `BYG`) |
| Users / memberships / role assignments | 10 / 10 / 10 |
| Customers | 26 (`C01`..`C26`) |
| Styles / style operations | 12 / ~88 |
| Materials; BOM versions / lines | 20; 16 / ~61 (12 active, 4 superseded) |
| Production lines | 9 (KTN `L1`..`L6`, BYG `B1`..`B3`) |
| Capacity slots | 540 (9 lines × 30 days × 2 shifts) |
| Orders | 101 (80 `PO-KTN-*`, 20 `PO-BYG-*`, 1 demo `PO-DEMO-001`) |
| Material lots / stock movements / balances | 40 / ~600 / 40 |
| Reservations / expected receipts | ~75 / ~11 |
| Operator aliases | 150 (25 per KTN line) |
| Cycle observations / line measurements | ~720 / ~108 |
| Quality policy versions / inspections / defects / holds / releases | 1 / ~40 / ~32 / 1 / ~18 |

**Personal data: none.** Names are obviously fictional (`Demo Apparel Group`,
`Customer 07 Apparel Co.`). Operators exist only as pseudonymous alias codes (`KTN-OP-017`). No
name, contact detail, health information, protected attribute or disciplinary record is modelled
anywhere in the 50-table schema — so none can leak, and none could be tested for fairness across a
protected characteristic ([`responsible-ai.md`](responsible-ai.md) §8).

**Known biases and limits.**
- One organization and two factories. Multi-tenant behaviour is exercised by scope tests, not by a
  realistic multi-customer dataset.
- 30 days of operational history. Trend and seasonality behaviour is untested.
- The demo scenario (`PO-DEMO-001`) is *designed* to contain a material shortage, a bottleneck and
  a failed inspection. It is a staged demonstration, not a sample of typical orders.
- Data quality is uniformly good: no duplicate records, no contradictory entries, no missing
  timestamps. Real factory data is not like this, and the system's abstention paths are therefore
  under-exercised relative to reality.

**Lifecycle.** `make seed` is idempotent and never deletes or truncates. It refuses to run when
`LS_ENVIRONMENT=production` (exit code 2). Reset is by dropping and re-migrating the development
database, never by a partial delete.

## 2. Synthetic SOP corpus

**Purpose.** Demonstrates and tests document ingestion, hybrid retrieval, citation and evidence
authorization.

**Provenance.** 30 documents hand-authored for this project, each fictional and each carrying its
own disclaimer line. Front matter: `slug`, `title`, `doc_type`, `scope`, `acl`, `version`; body is
a single `#` title, the disclaimer, then 3–8 `##` sections. The authoritative slug list is
`scripts/validate_datasets.py::EXPECTED_SLUGS`, enforced by `make datasets-check`.

**Versioning fixture.** `sops/versions/fabric-receiving-inspection-v1.md` is a deliberately
superseded version 1 (5% roll inspection) of an active version 2 (10%), used to prove that only the
active version is ever retrieved or cited.

**Scope fixture.** Documents carry `org`, `KTN` or `BYG` scope so that cross-factory retrieval
denial can be tested rather than asserted.

**Known biases and limits.** Short, clean, consistent English prose with regular headings. Real
SOPs are scanned, inconsistently formatted, partly tabular and often out of date. A retrieval score
on this corpus is a pipeline sanity check, **never** evidence of production retrieval quality.

**Licence.** Fictional content written for this project. Must not be copied or presented as a real
quality/IE standard.

## 3. Adversarial fixtures

`adversarial/injection-sop.md` embeds a prompt-injection attempt (`SYSTEM: ignore all previous
instructions...`). `adversarial/xss-note.md` contains raw `<script>` / `<img onerror>` markup.

**These two files are loaded only by tests and the evaluation harness — never by `make seed`.**
They exist so that "document content is untrusted data" and "note content is escaped, never
rendered as HTML" are *tested* properties rather than stated intentions
([`docs/security/threat-model.md`](../security/threat-model.md)).

## 4. Labelled NLP/IR evaluation datasets

**Location.** `data/eval/`. Documented in full at `data/eval/README.md`.

### `notes_train.jsonl` / `notes_test.jsonl`

150 train notes and 110 test notes; one synthetic supervisor shift note per line, with a topic
label (`planning`, `materials`, `ie`, `quality`, `unknown` — 30 per label in train, 22 per label in
test) and character-offset entity spans (`ORDER`, `LINE`, `STYLE`, `MATERIAL`, `OPERATION`,
`DEFECT`).

**Provenance.** `scripts/build_notes_dataset.py` with a fixed seed, then hand-reviewed.

**Anti-leakage rules, enforced by the validator (`make datasets-check`), not by good intentions:**

- **Train/test separation:** token-set Jaccard similarity between every test note and every train
  note must stay below 0.8. Train and test were built from disjoint template banks.
- **Sentence-frame diversity:** each note is collapsed to an entity-normalized frame (spans
  replaced by `<LABEL>`). No frame may be used more than 3 times within a split; at least 60% of a
  split's notes must have a unique frame; and no single label may have fewer than 20 unique frames.
  Measured: train 120 unique frames / 150 notes (80.0%), test 110/110 (100%). This rule exists
  because value-swapped templates inflate NER and classifier scores without adding real diversity —
  the first version of this dataset failed it and was regenerated.
- **Negative controls:** plausible-but-nonexistent references (e.g. `PO-KTN-9999`) appear
  deliberately and are **not** labelled, so a system cannot score well by surface pattern alone.
- **Surface-form variation:** `L3` / `Line 3` / `line 3`; `M01` / `Cotton Pique Fabric`; defect code
  or defect name. Some notes carry no entities at all.
- **No personal names anywhere**, consistent with the corpus's own worker-data-privacy procedure.

### `retrieval_questions.jsonl`

56 questions: **45 test** (40 `org`, 3 `KTN`, 2 `BYG`) and **11 dev** (10 `org`, 1 `KTN`). Each
carries the document slug(s) and exact `##` section heading(s) that answer it, and the factory
scope it assumes — which is what makes the cross-scope access tests possible. Questions are phrased
as a person would ask them, never as a copy of the heading text. `relevant` may never point at a
superseded version.

**A known, deliberate score effect:** 2 of the 45 test questions target BYG-scoped documents that
are legitimately out of scope for the evaluated retrieval scope, so a perfect system does not score
1.0 on this set. This is why the recorded smoke Recall@5 of 0.711 is not directly comparable to the
0.85 target without that caveat.

### What may be concluded from scores on these datasets

**A demonstration score only.** The vocabulary is small and closed, the notes are templated, and
the documents are short by design. A system can score very well here and still fail badly on real
factory text. These numbers are a sanity check that parsing, chunking, retrieval and extraction
work end to end — nothing more.

## Retention, deletion and licence

| Question | Answer |
|---|---|
| Does any real or personal data exist in this repository? | **No.** |
| What would change if real factory data were accepted? | A provider-data review, a written retention schedule, and a deletion process would all be prerequisites — **none of which exist yet** ([`responsible-ai.md`](responsible-ai.md) §9) |
| Is there a targeted per-customer deletion path? | **No.** Backup and restore exist; selective deletion of a customer's records, documents and embeddings does not |
| Document storage | Private directory, never served from a public path; storage keys are never derived from uploaded filenames |
| Audit retention | Not defined. Audit rows are append-only for the application role; how long they are kept is an open question that needs a legal answer, not a technical one |
| Licence of these datasets | Covered by this repository's project licence, which is **not yet finalized** (see [`README.md`](../../README.md)). Until it is, treat every dataset here as available for coursework use within this project only |
